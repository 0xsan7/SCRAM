# Post-release correctness audit — 2026-10-12

## Scope and outcome

The repository was cloned from GitHub at `1b557a87352ae784e67595adb8e2d6a128173dda`
into a disposable checkout, `/tmp/scram-bug-audit-20261012`, on branch
`codex/bug-audit`. The primary checkout and published release tags were not
modified. These are post-v0.2.0 fixes; the published v0.2.0 binary does not
acquire them automatically.

The investigation proceeded in repeated passes: write a reproduction, observe
the failure, fix the implementation, run the affected suite, then inspect
adjacent paths. Passing checks do not establish that the repository has no
remaining bugs. In particular, this audit does not claim a “last bug.”

## Reproduced defects and corrections

| Area | Failure established | Correction / regression |
|---|---|---|
| Policy file selection | `--config` was declared but ignored | Explicit config reaches scan.Run; a missing explicit file errors |
| Severity override | `--fail-on high` could display high while evaluating critical | Persistent CLI options use one engine adapter and the report uses the effective policy |
| JSON policy | Passing scans emitted `passed:false`; failure reasons were absent | Serialize the actual decision; preserve it during report conversion |
| Baseline location | Scanning another directory searched the caller's default baseline | Default baseline and trend paths belong to the scanned repository |
| Missing baseline | An explicitly requested missing baseline was silently ignored | Explicit missing/unreadable baselines are errors; ordinary first runs still work |
| SBOM failure | Bad formats or failed writes could exit successfully with zero files | Reject formats and propagate write errors |
| Baseline artifacts | `baseline update --sbom both` ignored the shorthand | Use the shared format expansion path |
| Dependency graph | “Dependents” traversed dependencies | Walk parent edges to find consumers |
| Multiple versions | Drift retained only one lexically selected version | Preserve exact identities; only pair a unique unmatched replacement |
| Advisory identity | Changing a representative ID appeared new/resolved despite shared aliases | Compare primary and alias identities across snapshots |
| Disclosure counts | New advisories on an unchanged version were absent from severity counts | Count new findings regardless of version change |
| Gate identity | An advisory new on one package gated old copies on another | Use component-specific drift entries for newness |
| Existing-finding mode | Combining new/all sets duplicated failure reasons | Gate the all-finding set once |
| Baseline format | Wrapped report JSON was accepted as an empty baseline | Validate baseline shape and preserve non-missing filesystem errors |
| Policy parsing | Misspelled settings and unsupported config versions were accepted | Decode known fields, require one document/version 1, normalize SBOM values |
| Ecosystem starter | Generated config excluded implemented Cargo support | Include Cargo in starter ecosystem selection |
| Source configuration | Independent NVD/GHSA settings were accepted without clients | Reject unsupported source combinations explicitly; OSV remains the matcher |
| Ignore paths | `ignore_paths` did not affect scanning | Apply validated glob patterns, including `**`, before discovery/parsing |
| Nested discovery | `apps/web/package-lock.json` became `web/package-lock.json` | Accumulate the full relative path; regression checks paths, not only counts |
| Discovery errors | A file could be accepted as a repository root; directory read errors disappeared | Require a directory and propagate included-directory read errors |
| Partial inventory | One valid file could hide failure to parse another | Mark the scan degraded; fail policy by default and reject incomplete inventory-only output |
| Trusted baselines | An OSV outage could produce a successful replacement baseline | Refuse to replace a baseline from incomplete scan data |
| Batch integrity | Missing/extra OSV result slots looked clean or misaligned | Validate positional result counts before attachment |
| Batch pagination | Additional OSV pages were silently omitted | Mark the scan incomplete rather than claim complete matching |
| Hydration identity | A detail response for a different advisory was accepted | Validate requested ID against remote and cached records |
| Package-specific fixes | One affected package supplied the fixed version for other packages, including warm-cache reads | Cache affected-package data and scope range summaries to each component |
| Score/vector pairing | Hydration could retain a larger score while replacing its vector with a lower-scored record | Update score/vector together and retain consistent existing pairs |
| CVSS equation | Scope-changed CIA weights were multiplied by a nonstandard factor | Use FIRST v3.1 base equations; the tested example changes 3.4 → 3.7 |
| CVSS parsing | Duplicate metrics, invalid scope/version, and malformed/out-of-range numbers scored | Reject malformed supported inputs |
| EPSS batches | A successful chunk concealed another chunk's failure | Preserve successful data and return the partial failure |
| EPSS values | NaN, infinity, and values outside 0–1 were accepted | Validate finite probabilities |
| Maintenance direction | Better Scorecard results increased risk | Convert to `round((10-score)/10*20)`; absent/inapplicable data stays unmeasured |
| Offline configuration | Policy offline mode could still fetch Scorecard | Honor the effective offline value across downstream stages |
| Cache expiry | Configured TTL did not reach Cache.Set | Propagate the effective TTL to the client |
| Shared cache data | Callers could mutate cached byte slices; memory cache lacked synchronization | Copy payloads and synchronize access |
| Cache writes | Writers shared the same temporary filename | Use unique temporary files and atomic rename; validate stored key/expiry |
| Git worktrees | Linked-worktree scans omitted source commit | Resolve gitdir/commondir indirection |
| Git metadata | Malformed HEAD/ref data could appear as commit metadata | Validate SHA values and reject traversal in ref paths |
| SBOM producer | SBOMs identified an old tool version | Carry generating CLI version into both formats and stamp the release SBOM hook |
| SBOM digests | Synthetic identity hashes were labeled package checksums; SPDX discarded real digests | Emit genuine supported supplied digests; retain identity/raw metadata separately |
| CycloneDX findings | Advisories had no affected-component references | Emit all affected PURLs and deterministic ordering |
| Mutation harness | INVALID mutants did not cause a failing exit status | Fail on invalid results; add a harness-level Python regression to CI |

The CVSS correction follows [FIRST CVSS v3.1 §7.1](https://www.first.org/cvss/v3.1/specification-document#7-1-base-metrics-equations).
The old scope regression and mutation expected the wrong arithmetic; both
were corrected rather than preserving an incorrect test oracle.

## Compatibility notes

- Maintenance-enabled scores change direction relative to v0.2.0. Severity
  scoring also changes for some scope-changed CVSS vectors. Refresh baselines
  deliberately after reviewing the change; do not compare old/new scores as
  though the calculation were identical.
- Unknown config fields, unsupported source requests, invalid formats,
  incomplete baselines, and partial inventories now fail explicitly.
- Drift retains multiple package versions. Ambiguous multiple replacements
  remain separate additions/removals instead of guessed version pairings.
- SBOMs may omit package checksums when no valid package digest is known.
  This is intentional. An identity hash cannot verify package bytes.
- The advisory detail cache uses a new namespace because old normalized entries
  did not retain affected-package ranges. Existing entries are refetched.
- Both SBOM formats and report schema version remain unchanged; semantics
  are corrected without adding a release tag.

## Remaining limitations

- Cache-backed offline vulnerability matching and persistent EPSS caching
  remain unimplemented; offline scans fail explicitly.
- Freshness data is not collected. The fixed `/65` presentation is not
  normalization over measured inputs or a calibrated compromise probability.
- Maintenance remains repository-level, not dependency-specific.
- Reachability, SLSA build attestations, and additional ecosystems remain
  roadmap work. Pagination is detected as incomplete rather than fetched.
- Package identity is preserved across versions, but per-project provenance
  of identical PURLs is still lost by global inventory deduplication.
- Advisory aliases and affected-range summaries depend on upstream metadata.
- Local validation cannot prove universal correctness or platform parity.
  Cross-platform CI and actual future release validation remain necessary.
