# Code of conduct

## The short version

Be direct. Assume the other person is competent and acting in good faith.
Disagree about the code, not about the person.

## What this project optimises for

A dependency scanner is trusted with a decision that blocks people's
work. Everything said about it should be checkable. That has a direct
consequence for how we argue here:

- **Show the run.** A claim about what the tool does is worth what the
  command that demonstrates it is worth. `go test ./...` and
  `python3 scripts/mutation_audit.py` are answers to most questions.
- **Say when you are unsure.** "I think this is wrong" and "this is
  wrong" are different claims and should not be written the same way.
- **Disagree with the number, not the person.** Most disagreements in
  this project have been about a measurement, and the measurement is not
  on anyone's side.

## Unacceptable

Personal attacks, harassment, sustained disruption, and publishing
someone's private information. There is no code of conduct police; the
maintainer handles reports, and will prioritise the report over the
project.

## Scope

Applies to the repository, the issue tracker, and any space where someone
is representing the project.

## Reporting

GitHub's private reporting, or the contact route in
[SECURITY.md](SECURITY.md) for anything security-sensitive.
